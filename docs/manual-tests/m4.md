# Manual test session after M4

M4 added checkout and commit: a track can be taken out of live editing, worked on alone, and
handed in as one commit that carries rendered samples everyone can play from the changelog. The
automated tests run the plan's demo between two clients and a real server (checkout, commit with
samples, a tempo change during a checkout, a forced release, a client restart). This session is
for what they cannot judge: whether the samples **sound** right, whether the locks are clear on
screen, and how the flow feels.

About 30 minutes, one machine.

## 0. Preparation

- [ ] **0.1** Run `cargo test --workspace --exclude 'spike-*'`.
      Expect: every line says `ok`, none says `FAILED`.
- [ ] **0.2** Run `cargo build -p mdaw-server -p mdaw-client`.
      Expect: it finishes without errors.

## A. One client alone

Start it with `cargo run -p mdaw-client`.

- [ ] **A1** Look at the track header of "Track 1".
      Expect: name, "M" and "×" as before, and **no** "Check out" button: checkouts need a server.

Close the window.

## B. Check out, commit, listen

The protocol changed again, so start the server with `--fresh` (it also forgets the demo
profiles). Three terminals:

```sh
cargo xtask server --fresh      # terminal 1: leave it running
cargo xtask client Ann          # terminal 2
cargo xtask client Ben          # terminal 3
```

Put the two windows side by side.

- [ ] **B1** Ann: click "+ Track" twice. Draw a one-bar clip at bar 1 on each track. Put four
      short notes into the clip of Track 1, one per beat, and two long low notes into the clip
      of Track 2.
      Expect: Ben's window has both tracks with their notes. Every track header in both windows
      has a "Check out" button between the name and "M".
- [ ] **B2** Ann: click "Check out" on Track 1.
      Expect: in Ann's window the button becomes a blue "Commit…". In Ben's window it becomes a
      brown "Locked", Track 1's clip is drawn dimmed, and the lane says "checked out by Ann" at
      its bottom left. Hovering "Locked" says Ann has it checked out.
- [ ] **B3** Ben: double-click the clip of Track 1 and click a note into the grid. Then click "M"
      on Track 1.
      Expect: no note appears, the track is not muted, and the notice strip says
      "This track is checked out by Ann."
- [ ] **B4** Ben: double-click the name of Track 1 and rename it to "Keys".
      Expect: it works, in both windows: the name and colour of a track stay live.
- [ ] **B5** Ann: add four more notes to Track 1 between the existing ones (on the off-beats) and
      move one note up an octave.
      Expect: Ann's window shows the changes, Ben's still shows the old four notes.
- [ ] **B6** Ann: press Space, listen through one bar, press Space again.
      Expect: both windows play together, each **its own** version of Keys: you hear the four
      old notes doubled, plus Ann's new ones once.
- [ ] **B7** Ann: click "Commit…".
      Expect: a window `Commit "Keys"` opens, shows "Rendering the samples…" for a moment, then
      "What did you change?" with a text field, "Listen before you commit:" with two buttons
      "Play: Track alone … s" and "Play: With the others … s", a "Commit" button, and below
      "Keep working" and "Drop changes".
- [ ] **B8** Ann: click "Play: Track alone".
      Expect: you hear the bar with Ann's new notes, Keys only, then a short release. The
      button reads "Stop: Track alone 1.2/… s" counting up while it plays and goes back to
      "Play: …" at the end. "Play: With the others" plays the same bar with Track 2's low notes.
      Clicking a playing button stops it.
- [ ] **B9** While the dialog is open, Ann: try to add a note to Keys.
      Expect: nothing changes; the notice says "This track is being committed."
- [ ] **B10** Ann: type "off-beats" into the text field, click "Commit".
      Expect: the dialog shows "Uploading the samples and committing…" briefly and closes. Ben's
      Keys now has Ann's notes and is no longer dimmed. Both windows show "Check out" on Keys
      again.
- [ ] **B11** Ben: open the "Changelog" tab.
      Expect: newest first, `Ann committed "Keys": off-beats` with "Play: Track alone" and
      "Play: With the others" beside it, and below `Ann checked out "Keys"`. Ann's changelog says
      the same with "you" in place of "Ann".
- [ ] **B12** Ben: click "Play: Track alone" in the changelog.
      Expect: after a moment (it downloads first) it plays what Ann heard in B8. It plays while
      the transport is stopped too, and also while it plays.
- [ ] **B13** Ben: add a note to Keys.
      Expect: it works and Ann sees it: the track is live again.

## C. Tempo changes during a checkout

- [ ] **C1** Ann: check out Keys and move one note. Ben: drag the tempo field (top bar,
      "120.0 bpm") down to about 90, let go.
      Expect: the tempo changes in both windows; Ben may change the tempo even though a track is
      checked out.
- [ ] **C2** Ann: click "Commit…".
      Expect: besides the usual parts, yellow text saying the tempo under this track changed since
      the checkout, and play buttons including "Play: Old tempo" and "Play: Current tempo". In
      place of "Commit" there are "Commit as is" and "Commit and restore the old tempo".
- [ ] **C3** Ann: play "Old tempo", then "Current tempo".
      Expect: the same music, the first at 120 bpm, the second slower at about 90.
- [ ] **C4** Ann: click "Commit and restore the old tempo".
      Expect: in both windows the tempo is back at 120.0 bpm and Ann's moved note is there. The
      changelog entry has play buttons including "Old tempo" and "Current tempo".
- [ ] **C5** Repeat C1 and C2, then click "Commit as is".
      Expect: the note is in, and the tempo stays where Ben put it.

## D. Ending a checkout: dropped, forced, kept working

- [ ] **D1** Ann: check out Keys, add a note, click "Commit…", then "Keep working".
      Expect: the dialog closes, the button still says "Commit…", and Ann can edit Keys again.
- [ ] **D2** Ann: "Commit…", then "Drop changes".
      Expect: the button turns into "Really drop them?". Click it once more: the dialog closes,
      Ann's new note is gone, Keys is free in both windows, and the changelog says
      `you dropped the checkout of "Keys"` (Ann) / `Ann dropped the checkout of "Keys"` (Ben).
- [ ] **D3** Ann: check out Track 2 and add three notes to it. Ben: click "Locked" on Track 2.
      Expect: a window "End the checkout?" explains that Ann's changes stay with Ann as a fork.
      Click "Cancel": nothing changes, Track 2 is still locked.
- [ ] **D4** Ben: click "Locked" again, then "End the checkout".
      Expect: Track 2 is free in both windows and Ann's three notes are gone from it. Ann's
      notice strip says "Ben ended your checkout. Your changes are kept as a fork in the
      changelog." The changelogs say `Ben ended your checkout of "Track 2"` (Ann) and
      `you ended Ann's checkout of "Track 2"` (Ben).
- [ ] **D5** Ann: select Track 2 and open the changelog.
      Expect: at the top, in yellow, `Your changes to "Track 2", kept when your checkout was
      ended` with "Restore as new track" and "Discard". Ben's changelog has no such line.
- [ ] **D6** Ann: click "Restore as new track".
      Expect: a new track "Track 2 (fork)" appears right below Track 2, in both windows, with the old
      notes of Track 2 **and** Ann's three. The fork line is gone.

## E. A checkout outlives its window

- [ ] **E1** Ann: check out Keys and add a note. Close Ann's window.
      Expect: Ben still sees Keys as "Locked".
- [ ] **E2** Wait a bit over a minute.
      Expect: Ben's button reads "Stale" and the lane text adds ", not heard from lately".
      Nothing else changes: the checkout is not ended by itself.
- [ ] **E3** Terminal 2: `cargo xtask client Ann`.
      Expect: the notice "Picked up the changes of your checkout from before." Ann's note is
      there, and the button says "Commit…". Within about ten seconds Ben's button is back to
      "Locked".
- [ ] **E4** Ann: commit it.
      Expect: as in B10.
- [ ] **E5** Ann: check out Keys again, add a note, and close Ann's window. Ben: click "Locked"
      (or "Stale") on Keys, then "End the checkout".
      Expect: Keys is free in Ben's window, without Ann's new note.
- [ ] **E6** Terminal 2: `cargo xtask client Ann`, and open the changelog with Keys selected.
      Expect: the notice "Your checkout of "Keys" was ended while you were away. Your changes are
      kept as a fork in the changelog." The fork line is there; Keys is free and has no new note.
- [ ] **E7** Ann: check out Keys once more.
      Expect: Keys as everyone has it, without the note from E5, and no "Picked up" notice. Click
      "Commit…", then "Drop changes" twice, to end it. Then "Restore as new track" on the fork:
      "Keys (fork)" appears right below Keys, with the note from E5.

## F. "As it was": hearing an edit that lost

- [ ] **F1** Both: open Keys's clip in the notes view. Press Ctrl+C in terminal 1.
      Expect: within about ten seconds both windows show "Reconnecting".
- [ ] **F2** Ann: drag one note of Keys up a few semitones. Ben: drag the **same** note down a
      few semitones.
- [ ] **F3** Terminal 1: `cargo xtask server` (without `--fresh`).
      Expect: both windows come back "Online" and end up with the same pitch for the note. Both
      changelogs list the edit that lost, as in the M2 session ("…, overwritten by …"), and after
      a few seconds a "Play: As it was … s" button appears beside it.
- [ ] **F4** Click "Play: As it was" in either window.
      Expect: Keys alone, with the note at the pitch that **lost**.

## Known gaps (not failures)

- **Samples come only from built-in instruments.** Tracks with plugins and their stems come
  with M6.
- **A sample is at most 8 bars**, plus a second of release. A changed mix or device setting
  plays the first 4 bars with notes. A track without notes gets no sample ("The track is
  silent").
- **A clip of a locked track can still be dragged.** On release it jumps back and the notice
  says why.
- **One commit at a time per window.**
- **A restored fork is a new track**; the original stays as it is.
- **The changelog** of a window that just opened holds the last 200 checkouts, commits and lost
  edits; plain edits are not listed at all. Lost edits of the tempo or the project name belong to
  no track and show only under "Whole project". A fork is listed under the track it came from,
  and only under "Whole project" once that track is removed. Lines from before today show the
  date as well.
- **"As it was" comes from the window whose edit lost**, and only while it is open at that
  moment.
- **Samples are downloaded when first played** and kept in memory until the window closes. The
  server keeps every uploaded sample forever.
- **Undo after a commit**: undoing an edit made during a checkout that is committed by now acts
  as a live edit.
- **Notes you play on the piano keys are heard only in your window.** Live MIDI comes with M5.
- Everything listed in the M3 protocol under Known gaps still holds.
