# Manual test session after M3

M3 added the shared clock and transport: play, stop, seek and loop are for everyone at once.
The automated tests check the logic and measure two clients against the server's clock (they
agree to well under a millisecond on one machine). This session is for what they cannot see:
whether two windows with real audio streams **sound** like one, and how the shared transport
feels to use.

About 20 minutes. One machine is enough; with both windows on one audio output, playing out of
step is easy to hear.

## A. One client alone (nothing changed)

Start it with `cargo run -p mdaw-client`.

- [ ] **A1** Look at the top bar.
      Expect: "Play", "Stop", "Loop" as before. There is **no** "Link" button and no small "clock"

## B. Two clients, one transport

The protocol changed, so the project of the M2 session cannot be opened: start the server with
`--fresh`. Three terminals, in this order:

```sh
cargo xtask server --fresh                # terminal 1: leave it running
MDAW_SYNC_LOG=1 cargo xtask client Ann    # terminal 2
MDAW_SYNC_LOG=1 cargo xtask client Ben    # terminal 3
```

Put the two windows side by side.

- [ ] **B1** Look at both top bars and at terminals 2 and 3.
      Expect: both windows have a highlighted "Link" button right of "Loop", and small grey text
      "clock ±0.0 ms" (or another small number) left of the green "Online: ..." text. Each
      client terminal prints about once a second a line like
      `sync: server time 12.345 s, playhead at tick 0, stopped, clock known to ±0.03 ms, 0 resyncs`.
- [ ] **B2** Ann: click "+ Track", draw a clip over bar 1, double-click it and click four notes
      into the grid, one on each beat, short ones. Ann: click "Loop". Then shift-drag in the
      ruler of the arrangement from bar 1 to bar 2.
      Expect: Ben's window has the track, the clip and the notes. "Loop" is highlighted in
      **both** windows, and both rulers show the loop region over bar 1.
- [ ] **B3** Ann: press Space. Watch **Ben's** window and listen.
      Expect: both windows start. Both buttons now read "Pause", both playheads run, both
      position displays count alike. **It sounds like one instrument**, louder than a single
      window was in A2: no doubled attacks, no echo.
- [ ] **B4** Look at the small grey text in both windows, then at terminals 2 and 3.
      Expect: the text now reads "in sync +0.0 ms" or a similarly small number (below 1 ms,
      either sign). The terminal lines read `audio +0.02 ms off the shared playhead` or similar
      in place of `stopped`, and still end in `0 resyncs`.
      Largest "off" value you saw: Ann ______ ms, Ben ______ ms
- [ ] **B5** Let it run for two minutes.
      Expect: it keeps sounding like one instrument. The "off" values stay small, `0 resyncs`
      stays.
- [ ] **B6** **Ben**: press Space.
      Expect: both windows stop. Both position displays show exactly the same position.
- [ ] **B7** Ben: click "Stop" (it is stopped already).
      Expect: both windows go to `1.1.1`.
- [ ] **B8** Ann: click "Loop" to switch it off, then click in the ruler at bar 3.
      Expect: "Loop" goes dark in both windows, and both playheads are at bar 3 (`3.1.1`).
- [ ] **B9** Ann: click "Stop" (back to `1.1.1`), click "Loop" on again and press Space. While it
      plays, Ben: click in the ruler in the middle of bar 1.
      Expect: both windows play the loop together. At Ben's click both jump to the place, are
      silent for a moment (see Known gaps), and go on together.
- [ ] **B10** While it plays, Ann: drag the tempo from 120 to about 90, let go. Then Ben: drag it
      to about 150, let go.
      Expect: both windows change pace together and sound like one instrument again once the

## Known gaps (not failures)

- **Starting takes a moment, and so does a jump while playing.** A start or a click in the ruler
  during shared playback is scheduled 150 ms ahead so that everyone gets there on the same
  sample. Stopped, or unlinked, a click in the ruler acts at once.
- **Dragging the tempo while it plays can click.** Every step of the drag moves the anchor of the
  transport, and each window takes that up with a small jump.
- **The server forgets the transport when it stops.** After a server restart everyone is stopped
  at the start with the loop off, whatever they were doing while it was away.
- **Two requests at the same moment: the later one wins as a whole.** If one person moves the loop
  in the very moment another clicks in the ruler, one of the two is lost.
- **Out of step is put right with a jump, not smoothly.** A client that finds itself more than
  20 ms off jumps (a click, and `resyncs` counts up). That should not happen within this
  session; if it does, it is a finding.
- **The playhead on screen runs ahead of the sound** by the output latency, a few milliseconds,
  alike in every window on one machine.
- **Notes you play on the piano keys are heard only in your window.** Live MIDI comes with M5.
- Everything listed in the M2 protocol under Known gaps still holds, except the first entry.
